# 部署与手机 / PC 验收

本文说明独立云服务仓库的部署步骤。请先复制本机配置模板，并将占位符替换为自己的 AppID 和云环境 ID。

## 1. 导入项目与选择环境

在微信开发者工具导入本仓库根目录，将 AppID 设置为自己的 `YOUR_WECHAT_APPID`。项目配置已指定 `miniprogram/` 和 `cloudfunctions/`。

打开云开发控制台，确认选择完整环境 ID `YOUR_CLOUD_ENV_ID`。环境需为可用状态，并已关联当前小程序 AppID。这里使用的是文档型云数据库 SDK，请确保环境启用了“云数据库”能力。

若控制台提示 Env invalid、Env Not Exists，先核对环境 ID、环境状态与账号关联；不要仅凭错误提示购买另一份套餐。

## 2. 创建数据库集合和索引

在上述环境创建以下集合：

| 集合 | 用途 |
| --- | --- |
| `life_users` | 每个用户的活动数据代次和修订号 |
| `life_records` | 业务记录、设置与删除墓碑 |
| `life_operations` | 请求去重及提交结果确认 |
| `life_imports` | 大批量导入的暂存状态 |
| `life_todo_reminders` | 待办订阅提醒登记、发送认领与结果 |

所有集合的客户端权限均设置为“仅管理端可读写”，或使用 `cloud/database.rules.json` 中的规则。云函数以可信微信上下文鉴权后访问数据库，**不能设为所有人可读写**。

在 `life_records` 添加复合索引：owner 升序、generation 升序、_id 升序。名称可用 `owner_generation_id`，字段定义见 `cloud/database.indexes.json`；如果控制台已有等价索引，不重复创建。

在 `life_todo_reminders` 添加复合索引：status 升序、remindAt 升序，名称可用 `status_remindAt`。

新版 `lifeButler` 在首次读取、登记或定时扫描时，若明确发现 `life_todo_reminders` 尚未创建，会尝试自动创建后重试。仍需在控制台核对集合权限为“仅管理端可读写”，并配置上述复合索引。创建权限不足、索引缺失或网络故障不会被当成“未开启通知”；页面保留待办操作，只显示简短提示和“重试”。部署新版云函数前，旧版本仍可能返回集合缺失错误。

## 3. 部署业务云函数

在开发者工具中将 `cloudfunctions` 关联到目标环境。右键 **`cloudfunctions/lifeButler` → 上传并部署：云端安装依赖**。

必须部署完整 `lifeButler` 文件夹，包含 `shared/`。其依赖在 package.json 中声明，无需把腾讯云密钥写入小程序。模板的 quickstartFunctions 不是业务数据入口，不需要部署它。

在云函数控制台确认运行环境支持 Node.js 18 或更高版本，将超时配置为 60 秒。代码中的 config.json 也记录了超时意图，但需以控制台实际配置为准。

客户端采用原生 wx.cloud，云函数中用 `getWXContext().OPENID` 获取用户身份。控制台直接测试通常没有小程序用户的 OPENID，因此直接运行 describe 得到 UNAUTHENTICATED 并不说明部署失败；应从小程序调用验证。

## 4. 云存储权限

云存储权限设置为“仅创建者可读写”；如使用自定义规则，采用 `cloud/storage.rules.json`。

照片路径为 `life-butler/{OPENID}/{唯一名称}.jpg` 等。图片上传、下载均通过微信云开发 SDK，业务记录保存 cloud fileID。

## 5. 验证云端连接

重新编译项目。首次加载成功后，“我的”页面会显示同步状态与最近同步时间。

如需在开发者工具 Console 手动检查，可执行：

```javascript
wx.cloud.callFunction({
  name: 'lifeButler',
  data: { action: 'describe' },
  config: { env: 'YOUR_CLOUD_ENV_ID' }
}).then(res => console.log(res.result)).catch(console.error)
```

预期 `ok:true`，含当前用户 openid、generation、revision。随后新增一条带照片的待办，确认云函数调用日志、life_records 中的记录、云存储中的照片都存在。

常见排查：函数不存在时重新上传部署；集合不存在时检查四个集合是否建立在相同环境；权限或非法环境错误时检查 AppID 关联和当前登录账号；图片失败时检查存储权限和配额。

## 6. 原数据迁移

1. 保留原项目与两端旧缓存，在各设备的原应用先导出含照片的完整备份。
2. 在云开发版进入“我的 → 备份与恢复”，选择备份文件并预览。若当前设备仍能访问原 KEY，也可点击“检查当前设备旧记录”。
3. 同编号但内容不同的记录、设置与学期信息需选择保留云端或使用导入内容。没有冲突的独立记录会保留并合并。
4. 点击“确认合并到云端”。另一个设备再迁移自己的旧备份，已相同的内容会去重。
5. 缺失照片会明确显示数量。确认继续时只能导入可恢复内容；需要保留照片时应返回原设备导出完整备份。

“确认恢复数据”是完整覆盖，不等于合并：它会替换同一账号所有设备的数据，并重置进行中的计时。覆盖和清空都有二次确认。

## 7. 双端验收清单（待部署后执行）

- [ ] 手机新增带图待办，PC 点击立即同步后看到文字和照片。
- [ ] PC 修改记录，手机返回前台或立即同步后看到修改。
- [ ] PC 删除记录，手机同步后不再显示；关闭并重开后仍一致。
- [ ] 两端同时修改同一记录，后提交的一端收到冲突提示且表单仍在。
- [ ] 断网保存明确失败，不提示成功；恢复网络后可继续同步。
- [ ] 使用另一个微信账号无法看到前一账号的记录。
- [ ] 导出完整备份并预览成功；先使用测试记录验证覆盖/清空，不直接对正式数据执行。

## 8. 待办到期服务通知

### 配置模板与定时器

1. 当前已按公众平台详情接入模板编号 **28327「任务截止日期提醒」**，模板 ID 为 `-aoXoECaHTnZ-41yWU47RekHdc295XkLN6cvNa8WgpM`，类型为一次性订阅。
2. `miniprogram/utils/reminder-config.js` 已填写四个字段：`titleKey: 'thing1'`（任务名称）、`timeKey: 'time3'`（截止日期）、`remainingKey: 'thing4'`（剩余时间）、`noteKey: 'thing5'`（温馨提示）。发送时按北京时间显示截止日期与时间，任务名称最多 20 字，剩余时间按发送时刻向上取整为分钟（如“剩余30分钟”），温馨提示为“待办即将到期，请及时完成”。更换模板时须同步核对全部字段。模板 ID 不是 AppID，也不需要 AppSecret。
3. 当前未上线联调使用 `miniprogramState: 'developer'`；体验版验收用 `'trial'`，正式发布前改为 `'formal'`。该参数控制通知点击后打开的版本，不会补充或修复云调用票据。修改后运行 `npm run sync-shared`，使客户端与云端采用同一模板配置。
4. 按第 2 节创建 `life_todo_reminders`、设置管理端权限及 `status_remindAt` 索引。
5. 上传并部署完整 `cloudfunctions/lifeButler`，包含 `shared/reminder-config.js`。确认云调用权限包含 `subscribeMessage.send`。右键云函数选择“上传触发器”或在控制台部署 `config.json` 中的触发器：名称 `todoDueReminders`，类型 timer，Cron `0 * * * * * *`（每分钟）。代码上传成功不代表触发器也已部署，请在控制台确认启用。
6. 上传匹配配置的小程序版本，在真机验收订阅授权及通知跳转。订阅授权由用户开启待办卡片的“到期通知”开关触发，页面加载或后台运行不会自动弹出授权。重新部署 `lifeButler` 以包含 `reminderStatus`、`reminderDisable` 接口，否则页面会提示通知设置暂不可用，点击重试可重新读取。

### 行为与运维

- 默认截止前 30 分钟提醒；在最后 30 分钟内开启时，下一轮检查尝试发送。检查时已过期则取消，因此距到期不到一分钟才订阅可能来不及发送。
- 一次订阅用于一条微信消息。已有待办、备份导入的待办不会自动订阅；改期后要重新开启提醒。该功能与“首页近期提醒”显示开关独立。
- 登记身份取可信 OPENID，发送对象和消息内容取云端记录；客户端不能指定他人接收通知。点击通知链接会在云端数据加载后打开对应待办；已删除的任务显示明确提示。
- 按用户、数据代次、任务 ID 和截止时间去重。重复点击、多个设备和定时器并发不会重复发送。同一截止时间已尝试发送的提醒不会因再次订阅而重发。改期或完成会推进云端提醒失效标记，即使又改回原状态，旧授权仍失效；尚未尝试发送的任务可经新订阅重新登记。仅修改标题或图片不取消提醒。
- 每次最多处理 40 条已到提醒时间的记录，其余留待下一分钟。用户量较大时须监控积压和云函数执行耗时；当前版本不承诺秒级送达。
- 记录状态为 `pending`（待检查）、`disabled`（用户关闭）、`sending`（已认领）、`sent`（微信接口确认成功）、`cancelled`（任务失效）、`failed`（接口明确拒绝）、`unknown`（发送结果不明）。失败原因保存在 `error`，云函数返回本轮发送/取消/失败数量。
- 新任务开关默认关闭，已登记的有效订阅保留开启状态。开关状态通过云端接口读取，跨设备在打开待办页或前台每 30 秒刷新。关闭时事务取消 pending；再次开启会申请新授权并递增 `subscriptionVersion`，使旧定时器快照无法取消或发送新订阅。已认领进入发送中的通知无法撤回，关闭失败时显示说明并刷新真实状态。
- 为避免超时后重复通知，只有 `pending` 可进入发送。网络异常或进程在认领后中断可能造成漏发；`unknown` 和长期 `sending` 需人工核实，**不要直接批量重置为 pending**。微信接口成功也不等于用户已阅读。
- 删除、完成、改期、清空或整库恢复后，定时器会取消失效的旧提醒。历史提醒文档暂不自动清理，可按运维保留周期整理已结束记录；不要清理仍有效的去重记录，否则可能允许同一任务再次发送。

### 真机验收

真实发送必须用手机小程序授权，并等待通过微信开发者工具上传的定时触发器执行。**不要用控制台“云端测试”模拟 Timer 验证真实微信发送**：即使有 OPENID，也可能没有有效 `wxCloudApiToken`。新版对 `wx_devtools`、`wx_localdebug` 来源的模拟定时事件返回 `WECHAT_TRIGGER_REQUIRED`，不认领任何提醒。依据见 [CloudBase 云调用票据限制](https://docs.cloudbase.net/faq/knowledge/missing-wxcloudapitoken-error)。

排查顺序：在微信开发者工具右键完整 `lifeButler` 上传并部署，再右键“上传触发器”；使用手机新增一个 5 分钟后到期的待办、开启通知并允许订阅，然后关闭小程序等待下一轮定时检查。新版按 SDK 可信 `SOURCE` 识别真正的定时触发，不再仅凭 OPENID 是否为空判断。日志中的 `todo-reminders:start` 应显示 `source: "wx_trigger"`。在 `todo-reminders:result` 中，`sent`、`cancelled`、`failed` 分别是本轮成功、取消、失败数量；失败原因查看对应提醒记录的 `error`。

若接口明确返回 `Invalid wxCloudApiToken` 或 `missing wxCloudApiToken`，新版保留 `pending`、记录 `lastAttemptAt` 和错误，让有效的后续定时调用重试；小程序显示“通知通道暂不可用，等待重试”。仅精确匹配这两类明确未受理错误；普通网络故障及其他参数错误仍保留 `unknown`，不会盲目重发。旧版本已经写入 `unknown` 的记录不会自动重置，请用新任务验收，避免将其他结果不明的记录误重发。

本地修改不会自动更新云端，需重新上传部署完整 `lifeButler`；已经过期的提醒不会补发。若真正的 `wx_trigger` 调用仍遇到票据错误，再核对云函数权限中的 `subscribeMessage.send`、小程序 AppID 与环境关联，以及触发器是否从微信 IDE 上传。

- [ ] 配置正确的模板及字段后，新任务“到期通知”开关默认关闭，开启时出现微信授权；未获授权时不登记提醒、恢复关闭状态，不误显示开启。
- [ ] 普通点击“取消”只提示已取消，开关保持关闭且可立即重试。若微信保存了拒绝选择或关闭订阅总开关，页面提供“去设置”；在设置中恢复接收后，返回再次开启开关并重新授权，才登记一次提醒。仅修改微信设置不自动登记。模板被后台封禁时显示限制说明，不能通过用户设置绕过。
- [ ] 开启后另一台设备进入待办页能看到开启；关闭后另一台设备刷新能看到关闭，且尚未发送的提醒不再发送。
- [ ] 关闭再开启需重新授权，旧定时器快照不能抢占新订阅；断网关闭失败时仍显示已确认开启并提示失败。
- [ ] 关闭已开启的通知时只更新业务状态，不将读取结果中的系统只读 `_id` 写回。关闭成功后另一设备能看到关闭；首次取消、设置读取失败或短暂授权失败都不会永久锁住开关。
- [ ] 为未来 5 分钟到期的未完成任务同意订阅，退出小程序，等待下一轮定时检查，微信收到一条包含任务名称与截止时间的通知。
- [ ] 点击通知进入对应待办；已被其他设备删除时显示“该待办已不存在”。
- [ ] 为未来一小时到期的任务开启提醒，确认截止前 30 分钟之外不发送；进入窗口后发送一次。
- [ ] 发送前完成、删除或修改截止时间后，旧提醒取消；改期后重新授权可登记新提醒。
- [ ] 截止时间 A → B → A、完成 → 恢复未完成，旧授权仍失效；重新同意订阅后可提醒尚未发送的任务。通知冷启动与已有待办页热启动都能打开目标任务。
- [ ] 重复点击或并发触发同一提醒只发送一次；另一个账号不能订阅当前账号的任务。
- [ ] 模板配置错误、微信拒绝发送、用户关闭订阅等情况有明确记录；通知失败不影响原有待办保存和同步。

## 本地测试工具异常

若 Codex 执行进程缺少 Windows 系统变量，可仅在当前 PowerShell 会话设置：

```powershell
$env:SystemRoot = 'C:\Windows'
$env:WINDIR = 'C:\Windows'
npm test
```

这不修改系统级环境变量。自动化测试覆盖的是模拟环境，不能替代上述真机清单。
